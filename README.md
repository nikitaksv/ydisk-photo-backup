# Яндекс Фото — резервная копия на Go

Скачивание фотографий и видео из безлимитного Photoslice Яндекс Диска с локальным архивом, продолжением после остановки и периодической проверкой качества. Сценарий Photoslice основан на [PXSYS13/yadisk_backup](https://github.com/PXSYS13/yadisk_backup); MIT-лицензия автора сохранена в [LICENSE](LICENSE).

## Сборка и запуск

Нужен Go 1.23 или новее. Бинарные сборки, данные аккаунта и cookies в репозиторий не включены.

Windows / PowerShell:

```powershell
git clone https://github.com/nikitaksv/ydisk-photo-backup.git
cd ydisk-photo-backup
go build -trimpath -o photoslice-go-ready.exe .
.\start.bat
```

WebUI: http://127.0.0.1:8789 . Папка Windows-помощника по умолчанию: `D:\YandexPhotoBackup`. Для другого расположения:

```powershell
.\Start-Backup.ps1 -OutputDirectory E:\PhotoBackup
```

Linux / macOS:

```sh
go build -trimpath -o photoslice-go-ready .
./photoslice-go-ready serve -listen 127.0.0.1:8789 -out ./backup
```

Закрытие вкладки не останавливает сервис. «Остановить» прерывает текущую очередь; для полного выключения заверши процесс сервера. Повторный `start.bat` открывает уже работающий сервис для той же папки.

## Подключение аккаунта

1. В Windows запусти `export-cookies.bat`. В других системах открой страницу расширений Chrome / Edge самостоятельно.
2. Включи режим разработчика, выбери «Загрузить распакованное расширение» и папку `cookie-helper`.
3. Войди в [Яндекс Диск](https://disk.yandex.ru/client/photo) в том же браузере, открой расширение и нажми «Сохранить cookies.json».
4. Загрузи JSON в раздел «Настройки» локального WebUI, проверь вход и запусти архивирование.

Помощник использует браузерный Cookies API, включая HttpOnly, и сохраняет файл локально. После экспорта расширение можно удалить. Cookies дают доступ к аккаунту: не публикуй их. При истечении сессии или CAPTCHA обнови вход в браузере и экспортируй новый файл.

## Загрузка и качество

- Два общих прохода: **сначала лучшие доступные превью всех известных файлов, затем оригиналы**. Оригиналы и серверные ZIP не запрашиваются, пока все работники не завершат проход превью; уже сохранённые превью пропускаются.
- Если превью недоступно и нет сохранённого оригинала, скачивается миниатюра как запасная копия. При наличии превью или оригинала дополнительная миниатюра не запрашивается. Все ранее полученные версии хранятся независимо: улучшение качества не удаляет старую копию.
- Прямые ссылки оригиналов обновляются по известным кластерам перед загрузкой. Продолжение использует сохранённый список без нового полного обхода Photoslice.
- Оригиналы, которые не удалось получить напрямую, накапливаются в постоянной ZIP-очереди SQLite. Серверные архивы загружаются последовательно пачками до 500 файлов. Совпадающие имена и оценка объёма более 8 GiB уменьшают пачку; последний неполный пакет от двух файлов отправляется после прямых попыток. Одиночные ZIP-запросы отключены.
- Успешные записи неполного ZIP сохраняются отдельно. Пропуски остаются для следующей периодической проверки и не отменяют всю пачку.
- В каждом проходе сначала обрабатываются фотографии, затем видео. Превью видео также проходят до любых оригиналов фотографий. JPEG-кадр видео учитывается как превью или миниатюра, а не как оригинал видео.
- Проверяются положительный размер, CRC / SHA-256, доступные размер и MD5 оригинала из API. Успех записывается для каждой версии отдельно после сохранения на диск.
- Уже скачанный, но не импортированный ZIP восстанавливается локально при продолжении. Оборванная сетевая версия скачивается заново; продолжения с конкретного байта нет.

Отдельный пакетный проход доступен в настройках WebUI и через `zip.bat`; полный режим сначала завершает проход превью. Диагностическая проба `zip.bat -Trial -BatchSize 500` проверяет только выбранную ZIP-пачку. При запуске полного ZIP-прохода через WebUI включается периодическая проверка; она сначала проверяет недостающие превью с миниатюрами как запасным вариантом, затем добирает оригиналы. Интервал по умолчанию — 6 часов. Проверка завершается, когда у всех известных файлов есть оригинал и превью; отдельная миниатюра для этого не требуется.

## WebUI

Компактный интерфейс в стиле TUI: «Обзор», «Файлы», «Журнал», «Настройки». Клавиши **1–4** переключают разделы, **R** обновляет данные. Пустые категории и неактуальные действия автоматически скрываются.

Обзор показывает число логических файлов с копией, лучшее качество, очередь ZIP, сетевую скорость, скорость новых файлов и место на диске. Скорость файлов переключается между секундой, минутой и часом. Прогноз относится к **первой копии каждого оставшегося известного файла**; он не обещает получение всех оригиналов и не подтверждает полноту аккаунта. В разделе файлов есть отдельный учёт наличия каждой из трёх версий и фильтры недостающих копий.

## Ошибки и ограничения частоты

HTTP 429 включает общую паузу всех работников с соблюдением `Retry-After`. Временное ограничение не считается отсутствием файла и не расходует обычные попытки. Пауза и сниженная частота сохраняются в SQLite после перезапуска. Уже начатые передачи могут продолжаться; после паузы запросы выпускаются постепенно.

Обычный начальный интервал — 500 мс для всех работников вместе. Автоподбор RPS постепенно снижает интервал на реальном трафике; при 429 возвращается к предыдущей ступени и прекращает разгон. Наблюдение без 429 не означает постоянную квоту Яндекса.

Проверка API ограничена 15 секундами. Медиа: до 8 секунд ожидания ответа и 8 секунд первого байта, до 30 секунд сетевого простоя после начала передачи, до 20 минут исправной передачи. Явные 404 / 410 сразу переключают качество; таймаут означает неподтверждённую доступность. По умолчанию 12 параллельных работников, допустимо 1–32. Метаданные не учитываются как скачанные фотографии.

## CLI

Примеры для Windows; в Linux / macOS используй `./photoslice-go-ready` и свою папку. Команды загрузки запускай при остановленной очереди сервиса: одновременная запись нескольких загрузчиков в одну папку блокируется.

```powershell
.\photoslice-go-ready.exe run -out D:\YandexPhotoBackup -workers 12
.\photoslice-go-ready.exe resume -out D:\YandexPhotoBackup
.\photoslice-go-ready.exe zip -out D:\YandexPhotoBackup -batch-size 500
.\photoslice-go-ready.exe zip -out D:\YandexPhotoBackup -batch-size 500 -max-batches 1
.\photoslice-go-ready.exe upgrade -out D:\YandexPhotoBackup
.\photoslice-go-ready.exe watch -out D:\YandexPhotoBackup -interval 6h
.\photoslice-go-ready.exe stats -out D:\YandexPhotoBackup -json
.\photoslice-go-ready.exe list -out D:\YandexPhotoBackup -filter missing-original
.\photoslice-go-ready.exe verify -out D:\YandexPhotoBackup
.\photoslice-go-ready.exe report -out D:\YandexPhotoBackup
```

`run` перечисляет Photoslice; `resume` продолжает по сохранённому списку; `upgrade` проверяет недостающие версии известных файлов; `watch` повторяет проверку через заданный интервал. Cookies по умолчанию читаются из папки данных; другой путь задаётся `-cookies`. Ctrl+C останавливает CLI.

`stats` и `list` поддерживают `-json`, `list` — `-offset` и `-limit` 1..100. Фильтры: `all`, `original-best`, `preview-best`, `thumbnail-best`, `missing-original`, `missing-preview`, `missing-thumbnail`, `no-copy`, `failed`, `pending`.

## Формат архива и метаданные

Обычные версии сохраняются в `archives/<префикс>/<id>-<качество>-<хеш>.zip`; медиа внутри записывается без повторного сжатия. В ZIP входят неизменённые байты медиа, `metadata.json`, очищенные от секретов и подписанных URL метаданные API и доступный извлечённый EXIF-блок.

Серверные ZIP хранятся без перепаковки в `zip-batches/`, рядом — манифест с запрошенными файлами, проверенными записями, хешами, метаданными и пропусками. База `state.db` хранит прогресс, каждую версию и ошибки. В статистике `archives` — историческое имя числа сохранённых **версий**, `archive_files` — физические ZIP, `zip_archives` — пакетные ZIP.

Сохраняются полные доступные даты, доли секунды и смещение часового пояса, источник даты, подписи и остальные доступные поля API. EXIF сохраняется отдельно, когда доступен. Отсутствующий часовой пояс не выдумывается; исходные байты медиа не переписываются. Данные о файле остаются в БД и при отсутствии всех медиа-копий.

После завершения или остановки создаются `report.csv`, `metadata.jsonl`, `summary.json`. После аварийного закрытия пересоздай отчёты командой `report`. CSV содержит одну строку на логический файл с качеством, датой и сведениями обо всех версиях.

## Проверка исходников

```sh
go test -timeout 60s ./...
go vet ./...
```

Используется внутренний API Яндекса, который может меняться. Программа сохраняет доступные серверу версии; недоступные файлы остаются в отчёте для повторных проверок. Полнота списка отмечается отдельно от успешности скачивания. Этот проект переносит сценарий Photoslice; функции обычного Диска, сортировки и дедупликации исходного Python-проекта не перенесены.
